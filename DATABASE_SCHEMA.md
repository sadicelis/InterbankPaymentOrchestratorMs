## 🗄️ Detailed Definition of Tables

### 1. **TRANSACTION** (Principal)


|  Column | Type | Restrictions| Indexes | Description |
|---------|------|-------------|---------|-------------|
| `id` | UUID | PK, NOT NULL | CLUSTERED PRIMARY KEY | Unique transaction identifier |
| `reference` | VARCHAR(50) | UK, NOT NULL | UNIQUE INDEX | Unique reference generated by the client/system |
| `source_account` | VARCHAR(20) | FK (BANK), NOT NULL | NON-CLUSTERED | Originating bank (sender's account) |
| `destination_account` | VARCHAR(20) | NOT NULL | NON-CLUSTERED |Destination bank (beneficiary account) |
| `amount` | DECIMAL(18, 2) | CHECK > 0, NOT NULL | NON-CLUSTERED |Amount to transfer (18 digits, 2 decimal places) |
| `bank_id` | VARCHAR(20) | FK (BANK), NOT NULL | NON-CLUSTERED | processor bank (BANK_1, B2, etc.)|
| `status` | VARCHAR(20) | FK (PAYMENT_STATUS), NOT NULL | NON-CLUSTERED | Current status (PENDIENTE, EXITOSA, FALLIDA) |
| `created_at` | TIMESTAMP | NOT NULL, DEFAULT GETUTCDATE() | NON-CLUSTERED | Date/time of creation |
| `updated_at` | TIMESTAMP | NULL | NON-CLUSTERED | Latest status update |

**Purpose**: To store all interbank transactions with full auditing.

**Recommended Indexes**:
```sql
-- Quick search by reference
CREATE UNIQUE INDEX IX_TRANSACTION_REFERENCE ON TRANSACTION(reference);

-- Search for pending transactions
CREATE INDEX IX_TRANSACTION_STATUS_CREATED ON TRANSACTION(status, created_at);

-- Analysis by bank
CREATE INDEX IX_TRANSACTION_BANK_ID ON TRANSACTION(bank_id);

-- Reconciliation by date
CREATE INDEX IX_TRANSACTION_CREATED_AT ON TRANSACTION(created_at DESC);
```

### 2. **PAYMENT_STATUS** (Catalog)

| Column  | Type | Constraints | Description |
|---------|------|-------------|-------------|
| `code` | VARCHAR(20) | PK, NOT NULL | Status code (PENDIENTE, EXITOSA, FALLIDA) |
| `description` | VARCHAR(255) | NOT NULL | Legible description (e.g., "Pending bank confirmation") |

**Possible values**:

|  Code  | Description |
|--------|-------------|
| `PENDIENTE` | Pending confirmation from the external bank |
| `EXITOSA` | Transfer completed successfully |
| `FALLIDA` | Transfer rejected by bank |

---

### 3. **BANK** (Bank Catalog)

| Column  | Type | Constraints | Description |
|---------|------|-------------|-------------|
| `id` | VARCHAR(20) | PK, NOT NULL | Unique identifier |
| `code` | VARCHAR(50) | NOT NULL | Code identifier (BANK1, BANK2, etc.) |
| `name` | VARCHAR(100) | UK, NOT NULL | Bank name (Bank1, Bank2) |
| `active` | BIT | NOT NULL, DEFAULT 1 | Indicates if the bank is active (1) |
| `created_at` | timestamp | NOT NULL| Date/time of creation |

## 🔍 Common Queries

### Get all pending transactions from a bank:
```sql
SELECT t.* 
FROM TRANSACTION t
WHERE t.bank_id = 'BANK1' 
  AND t.status = 'PENDIENTE'
  AND t.created_at > DATEADD(hour, -2, GETUTCDATE())
ORDER BY t.created_at DESC;
```

### Reconciliation: Transactions completed without updating DB:
```sql
SELECT t.* 
FROM TRANSACTION t
WHERE t.status = 'EXITOSA' 
  AND t.updated_at IS NULL;
```

### Transfer statistics by bank:
```sql
SELECT 
    t.bank_id,
    COUNT(*) as total_transfers,
    SUM(t.amount) as total_amount,
    COUNT(CASE WHEN status = 'EXITOSA' THEN 1 END) as successful,
    COUNT(CASE WHEN status = 'FALLIDA' THEN 1 END) as failed
FROM TRANSACTION t
WHERE t.created_at >= DATEADD(day, -30, GETUTCDATE())
GROUP BY t.bank_id
ORDER BY total_amount DESC;
```

### Audit: All transactions of a user/reference:
```sql
SELECT * 
FROM TRANSACTION 
WHERE reference LIKE 'USER123%'
ORDER BY created_at DESC;
```
